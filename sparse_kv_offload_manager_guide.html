SparseKVOffloadManager
稀疏 KV 卸载管理器图解

它把 SFA / MLA 的历史 KV 放进 CPU DRAM，NPU 上只保留注意力真正会读到的 top-k 命中行。调度器看到的 block 数因此被 DRAM 扩容，进而支持更长的 max_model_len 或更大的 decode batch —— 而复用的仍是上游那套 block_table / slot_mapping。

01

它到底省了什么

关键不是"把 KV 挪走"，而是只把一次注意力真正需要的那部分挪回来。 稀疏注意力（SFA / DSA）每步只用 top-k 个历史 token，所以 NPU 上真正需要常驻的， 是每层每行的 topk_buffer_size 个槽位，而不是整条序列。

一句话记忆：CPU 池是"真身"，NPU 热行是"工作台"。每次 decode 把新 token 的 KV 从计算现场直接写进真身（D2H），再把 top-k 选中的旧 token 搬到工作台（H2D）， 注意力只读工作台。
02

结构图：谁持有哪块内存

五类角色：上游调度器（只提供 block_table / slot_mapping）、注意力后端（每层调用）、 manager（唯一的编排者）、memfabric DMA 层、以及 CPU 侧的纯 host 算子。

1Scheduler → Attention：block_table / slot_mapping 原样透传 2Attention → Manager：每层 exec_kv 后调用 offload_new_kv 3Manager → CPU 算子：打包参数，调用 planner 与地址计算 4CPU 算子 → memfabric：输出 gvas / addr / size 描述符 5memfabric ↔ CPU 池：D2H 写新 KV，H2D 读 miss 行 6Manager → memfabric：offload.sparse_copy 一次批量搬运 7memfabric → NPU 热行：按 slot 写入 resident row 8Manager → NPU：current_slots、resident 视图参数 9Attention → NPU 热行：稀疏注意力只读热行 10Attention → Manager：进入注意力前 onload_topk_kv
注意层级：热行是 per-layer 的 —— topk_buffers_k[layer_id]。 每层都有自己的 top-k 选择结果，因此 CPU 侧也按层维护一套 lru_slot_to_token。

# sparse_kv_offload_manager.py:38-45
# Main KV cache:
# [k_cache, v_cache, k_cache_cpu, v_cache_cpu, topk_buffer_k, topk_buffer_v].
# A BF16 main cache fills all six slots. A packed SFA main cache (C8 or TQ4)
# stores one byte row per token, so the V slots alias the K slots and the
# offload kernels keep their K/V-pair contract by copying the same row twice.
OFFLOAD_KV_CACHE_TUPLE_LEN = 6

BF16 主 KV：双 leg main_leg_count = 2

K 维度取 kv_lora_rank，V 维度取 qk_rope_head_dim。 两个热行一起分配再切开，保证 K / V 的 data_ptr 差值在所有层恒定 —— 这样 skip_topk 时只需平移一个 delta 就能换层。 

# 先一整块，再 split（对齐原因）
topk_buffer_raw = torch.empty(
  [k_bytes + v_bytes], dtype=torch.int8, device="npu")
topk_buffer_k = topk_buffer_raw[:k_bytes].view(torch.bfloat16)...
topk_buffer_v = topk_buffer_raw[k_bytes:].view(torch.bfloat16)...

packed 主 KV：单 leg main_leg_count = 1

每个 token 只有一行字节，K/V 两半与 scale 都打包在行内。 因此 v_tensor_size is None： 设备与 host 的 V 槽位都留空，热行 K/V 指同一块内存。

这会带来 2× 拷贝带宽（同一行被写两遍），但零额外 HBM， 且不用改 C++ 侧写死的"K/V 双段"契约。
为什么不是 7 元组？稀疏 LI 的 C8 indexer 缓存是 device-resident，不参与卸载，也不注册给这个 manager —— 所以元组只描述"主 KV"的 6 个槽位。

热行替换：命中留下，未命中补货

每层有 lru_slot_to_token[rows, topk_buffer_size]： 槽位 → 当前放的 token。新 top-k 列表到达后，已在驻留集合里的是命中（不动）， 其余从空槽或最久未用的槽补进来。下面是概念演示（非精确实现）。

# 源：miss token → CPU 池绝对地址
src = gvas_base[layer] + block_table[row][token // block_size] * block_bytes \
      + (token % block_size) * token_bytes

① 求交

对新 top-k 与 slot_to_token 做集合运算，产出 miss_count / miss_tokens / miss_slots。

② 选槽

优先空槽；否则淘汰最久未用的可淘汰槽，并把旧 token 标记失效。

③ 编址

每个 miss 生成一条 (gvas, addr, size)， 非法行 size 置 0，天然跳过。

skip_topk 的省法：同一批 token 的所有层 top-k 相同，只有热行/池基址不同。 源码直接断言层间 K/V 的基址差相等，然后把两个描述符数组整体 += delta，跳过整个 planner 与编址 —— 这是"层间 delta 恒定"设计的回报。
08

TP 共享与 PD 分离

只有 TP0 真正分配 host 池并写 decode KV（decode KV 在 TP 间本来就被复制）； 其他 rank 通过广播得到的 GVA 读同一块 host 内存。PD 分离时，D 节点把 P 节点 拉来的 KV 直接落进这个池，本地注意力再从池里补货。

TP 内的协作 无需 barrier

TP0：写 + 算

_offload_new_kv_on_current_stream

只有 TP0 会往下走；tp_rank != 0 直接 return。

广播元信息

tp_group.broadcast(gvas / block_len / shape)

TP0 分配后把指针与形状广播；其他 rank 用 sparse_kv_restore_*_tensor 还原成本地视图。

栅栏用空 tensor

tp_group.broadcast(torch.empty([], int8), src=0)

目的：保证 TP0 的 D2H 已落池，再让其他 rank 的 H2D 去读。 不能用 barrier，因为它无法被 graph 捕获。

门槛、约束与坑

逐条对应源码里的 assert / raise / logger 位置，便于排查。

类别约束级别
平台必须支持 HardwareCapability.SPARSE_KV_OFFLOAD（Atlas A3 / Ascend950）硬闸门
算子_C_ascend 必须存在 7 个 sparse_kv_* 算子，且 vllm_ascend_C 可加载硬闸门

三个真实陷阱

no-op 不等于成功。offload.sparse_copy 返回值必须检查： if result not in (None, 0): raise，否则丢数据无声无息。
非法 slot 靠长度 0 屏蔽。不要跳过写描述符 —— 位置和条数必须与 slot_mapping 一一对应，只是 length 置 0。
层数不等于 target 层数。mtp_layer_id = num_layers - 1 只在 num_layers != num_target_layers 时成立， MTP 层元数据不能复用上一层。
